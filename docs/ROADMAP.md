# ALGI GROUP — план разработки

Статус на 31 июля 2026 года. Исходные `*.dc.html` считаются дизайн-прототипами и источником контента, но не production-кодом.

## Спринт 0 — фундамент и границы проекта

**Результат:** архитектура, карта данных, юридическая матрица, перечень неподтверждённых реквизитов, критерии приёмки.

- [x] Инвентаризация 11 прототипов и `BACKEND_PROMPT.md`.
- [x] Выбор монорепозитория: публичный web + API + общая Prisma-схема.
- [x] Базовая legal/compliance-матрица.
- [x] Постатейная сверка ключевых норм в редакциях на 31.07.2026.
- [ ] Подтверждение реальных реквизитов, контактов, способов оплаты и доставки владельцем.

## Спринт 1 — данные и API

**Результат:** локально поднимаются PostgreSQL/Redis и API; каталог читается из БД; лид сохраняется до попытки уведомления.

- [x] Docker Compose, env-шаблон и workspace.
- [x] Первая production-ориентированная Prisma-схема.
- [x] Миграции и seed: 3 бренда, 3 страны, 9 коробок по 10 дрип-пакетов.
- [x] Поля GTIN/ТН ВЭД/ОКПД2 и учёт кодов маркировки кофе по ПП РФ №1682.
- [x] Публичные API каталога и лидов, валидация, rate limit, honeypot.
- [x] Надёжный Telegram-outbox с retry/lock и без персональных данных по умолчанию.
- [x] Unit-тесты валидации/паролей и интеграционная проверка API.

**Результат:** адаптивные страницы из макетов, SEO, доступность, работающий каталог и формы.

- [x] Корзина на клиенте с серверной сверкой цены и остатка при заказе.

**Результат:** заказ с ценовым снапшотом и резервом, оплата, чек и доставка.

## Спринт 4 — админка

**Результат:** сотрудники управляют товарами, остатками, заказами, лидами и контентом.

- [x] CRUD каталога/вариантов, воронка лидов, заказы и дашборд API; базовый web-интерфейс.
- [x] Audit log и rate limit; same-site cookie защищает текущий раздельный admin-origin.
- [ ] Медиа-хранилище, экспорт и полноценный редактор партий.

## Спринт 5 — compliance и безопасность

- [x] CI для build/test/audit; production dependency audit: 0 уязвимостей на 31.07.2026.
- [ ] CD и backup/restore rehearsal после выбора российского хостера.
- E2E критических путей, мобильная/кроссбраузерная и accessibility-проверка.
- Метрики, алерты, журналирование без ПДн, runbook и rollback.

## Решения, которые нужны от владельца

1. Заполнить реальные реквизиты продавца в переменных окружения по `docs/CONFIGURATION.md`; значения из HTML-макетов не используются приложением.
2. Указать официальный email для запросов субъектов ПДн и ответственного за обработку.
3. Выбрать российского хостера/ЦОД, платежного провайдера, ОФД, оператора доставки и email/SMS-провайдера.
4. Утвердить реальные товары, цены, остатки, характеристики пищевой продукции и документы о соответствии.
5. Уточнить, нужна ли рекламная рассылка. Без отдельного согласия она будет выключена.
