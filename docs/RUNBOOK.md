# Production runbook

## До первого запуска

1. Выбрать сервер и управляемую PostgreSQL с физическим размещением первичной базы персональных данных в России.
2. Заключить и проверить договоры с хостером, ЮKassa/кассой, ОФД, СДЭК и иными обработчиками. Зафиксировать поручения на обработку ПДн и расположение систем.
3. Заполнить `.env.production` реальными реквизитами и секретами. Не копировать dev-пароли.
4. Подать требуемые уведомления оператором в Роскомнадзор до начала обработки; трансграничное уведомление выполнять отдельно до передачи данных за рубеж, если такая передача фактически появится.
5. Утвердить политику, согласия, оферту, возврат и сроки хранения. Черновые legal-страницы не являются юридическим заключением.
6. Проверить GTIN, ТН ВЭД, ОКПД2, декларации соответствия, этикетки и готовность к обязательной маркировке кофе.

## Выпуск

```sh
docker compose -f deploy/docker-compose.production.yml build
docker compose -f deploy/docker-compose.production.yml run --rm migrate
docker compose -f deploy/docker-compose.production.yml up -d
docker compose -f deploy/docker-compose.production.yml ps
```

После запуска проверить `/healthz`, каталог, форму лида, тестовый заказ, тестовый платёж, чек, webhook, снятие резерва, Telegram и вход каждой роли. Затем удалить `ADMIN_BOOTSTRAP_PASSWORD` из окружения и перезапустить API.

## Резервное копирование

- Ежедневный зашифрованный backup PostgreSQL хранить в российском контуре с отдельными ключами и ограниченным доступом.
- Не реже раза в квартал выполнять восстановление в изолированной среде и документировать результат.
- В backup входят персональные данные: сроки удаления и доступ должны соответствовать основным системам.

## Инцидент с персональными данными

1. Ограничить утечку, сохранить технические доказательства и не распространять ПДн в чатах.
2. Зафиксировать время, категории данных, объём, причины, последствия и принятые меры.
3. Передать ответственному за ПДн и руководителю.
4. Соблюсти сроки уведомления Роскомнадзора: первичное уведомление — 24 часа, результаты внутреннего расследования — 72 часа.
5. Сменить затронутые ключи, проверить журналы и документировать корректирующие меры.

## Откат

Приложение откатывается на предыдущий immutable image. Миграции БД назад автоматически не выполняются: перед несовместимой миграцией создаётся проверенный backup и готовится отдельный план восстановления.
